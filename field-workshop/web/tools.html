Optional command reference

The workshop can be completed entirely in the browser on Windows and Mac. Use Fault injection to create the problem and Fallbacks & timeouts to change the shop's response.

You do not need to type any of the commands below. The console's Info & commands tab also shows the last request with a Windows/Mac selector.

What changes when I enable a fallback?

Inventory fallback returns Stock unconfirmed if stock cannot be checked. Shipping fallback keeps the preview useful with Shipping quote unavailable. A timeout limits the dependency wait. These controls change the real running Storefront immediately; they do not remove the injected fault or restart the container.

Restore defaults in Fallbacks & timeouts, then clear the fault in Fault injection. Your answers remain saved. Runtime settings last until Storefront restarts and reloads its startup configuration.

Windows · PowerShell

Inventory timeout and fallback

Invoke-RestMethod -Method Post -Uri 'http://localhost:8089/api/mitigations' -ContentType 'application/json' -Body '{"action":"configure","dependency":"inventory","timeoutMs":400,"fallback":true}'

Shipping fallback

Invoke-RestMethod -Method Post -Uri 'http://localhost:8089/api/mitigations' -ContentType 'application/json' -Body '{"action":"configure","dependency":"shipping","timeoutMs":3000,"fallback":true}'

Restore default settings

Invoke-RestMethod -Method Post -Uri 'http://localhost:8089/api/mitigations' -ContentType 'application/json' -Body '{"action":"reset"}'

Inventory latency

Invoke-RestMethod -Method Post -Uri 'http://localhost:8089/api/action' -ContentType 'application/json' -Body '{"action":"set-latency","proxy":"inventory","latencyMs":1500}'

Mac · Terminal

Inventory timeout and fallback

curl -f -sS -X POST 'http://localhost:8089/api/mitigations' -H 'Content-Type: application/json' --data '{"action":"configure","dependency":"inventory","timeoutMs":400,"fallback":true}'

Shipping fallback

curl -f -sS -X POST 'http://localhost:8089/api/mitigations' -H 'Content-Type: application/json' --data '{"action":"configure","dependency":"shipping","timeoutMs":3000,"fallback":true}'

Restore default settings

curl -f -sS -X POST 'http://localhost:8089/api/mitigations' -H 'Content-Type: application/json' --data '{"action":"reset"}'

Inventory latency

curl -f -sS -X POST 'http://localhost:8089/api/action' -H 'Content-Type: application/json' --data '{"action":"set-latency","proxy":"inventory","latencyMs":1500}'

What happens underneath?

Fault requests change the real Toxiproxy paths. Mitigation requests change the Storefront's live timeout and fallback policies through an internal Docker listener. No Docker socket or host shell is exposed to the console.
